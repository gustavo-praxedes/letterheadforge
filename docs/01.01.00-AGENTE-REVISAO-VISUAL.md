# Agente de Revisão Visual

Subagente especializado (AGENTS.md §1.1). Avalia a interface **apenas pelas imagens**.

## 1. Contrato de entrada

O agente recebe:

1. Uma pasta de capturas: `temp/shots/<revisao>/`, com PNGs nomeados `NN-<tela>[-<estado>].png`.
2. Um arquivo `manifest.json` com `{ url, viewport, theme, shots: [{ file, label }] }`.
3. O checklist visual da rodada (itens objetivos, verificáveis na imagem).

O agente **não** recebe: HTML, CSS, JS, diff, log de console, stack trace, mensagem de erro de ferramenta, nem caminho de código. Se precisar de algo que a imagem não mostra, a resposta é `precisa-nova-captura` com a tela e o estado desejados.

## 2. Checklist visual (Marco 2 em diante)

| Id | Item | Como verificar na imagem |
|---|---|---|
| V1 | Hierarquia | Painel de configuração à esquerda, preview à direita; nada sobreposto |
| V2 | Alinhamento | Bordas de painéis, campos e rótulos alinhados em grade visível |
| V3 | Contraste | Texto legível sobre o fundo; nenhum texto cinza-claro sobre branco |
| V4 | Densidade | Sem áreas vazias grandes nem campos amontoados; espaçamento uniforme |
| V5 | Preview fiel | A folha no preview tem as proporções do tamanho escolhido |
| V6 | Estados | Selo/ação desabilitada visivelmente diferente da habilitada |
| V7 | Avisos | Aviso visível, com texto legível e sem cobrir conteúdo |
| V8 | Mobile | Na largura de 390 px, abas e conteúdo sem corte horizontal |
| V9 | Foco | Anel de foco visível no elemento focado |
| V10 | Idioma | Todo texto em pt-BR consistente, sem trechos em inglês |

## 3. Procedimento

1. Ler `manifest.json` e o checklist da rodada. Nada além.
2. Abrir cada PNG. Se um item não for verificável em nenhuma captura, marcar `nao-verificavel` e pedir a captura que falta.
3. Veredito binário por item: `passa`, `falha` ou `nao-verificavel`.
4. Cada `falha` precisa de: id do item, arquivo da captura, descrição em uma linha e coordenada aproximada `(x, y)` em pixels.
5. Resumo final: `aprovado` só quando todos os itens aplicáveis passam. Caso contrário, `reprovado` com a lista de falhas.
6. Nunca sugerir mudança de código. Descrever só o efeito visual esperado.

## 4. Geração das capturas

`scripts/shots.mjs` (Playwright headless, Chromium instalado por `npx playwright install chromium`):

```bash
npm run serve &                 # http://localhost:8080
npm run shots -- --revisao m2-01 --url http://localhost:8080/ [--theme light] [--mobile]
```

- Grava `temp/shots/<revisao>/*.png` e `manifest.json`.
- Telas e estados vêm de `scripts/shots.config.json` (lista de `{ label, path, actions, waitFor }`), para não haver roteiro fixo no código.
- Sem `--url`, usa `http://localhost:8080/`.
- O script não interpreta as imagens: só captura e informa caminhos.

## 5. Limites

- Três rodadas por frente; a quarta não acontece — o bloqueio sobe ao principal (AGENTS.md §4).
- O agente visual não aprova tarefa sozinho: o checklist do plano decide, e a revisão visual é um dos itens dele.
